# Working Rules

- One repository is the source of truth; keep project notes in Markdown.
- Every learning topic connects to a practical pharmacy/healthcare task.
- Prefer public or synthetic data; document provenance and terms.
- Use small, reviewable commits with clear messages.
- Never upload secrets, API keys, passwords, private records or identifiable patient data.
- Make notebooks reproducible: state assumptions, dependencies and random seeds.
- Separate exploratory analysis from validated conclusions.
- Add tests before calling a workflow reliable.
- Record limitations and unsafe use cases.
- Avoid paid subscriptions unless a specific need is justified.
